# Larda: общий frontend + API + PostgreSQL

Основной режим использует сервер. Локальные синтетические данные не подставляются при ошибке API. В рабочем пространстве выбирается демопрофиль бизнеса, капитана или участника; это не production-авторизация.

## Сейчас на этой машине

- Проверочный интерфейс: http://127.0.0.1:3000 (Vite preview, серверный режим).
- API: http://127.0.0.1:8080; `/healthz` отвечает `{"status":"ok"}`.
- PostgreSQL: Podman-контейнер `larda-integration-db`, порт 55432, постоянный volume `larda-integration-db`.
- Нативный API на 8080 перезапущен с `AI_MODE=openai` из существующего `.env`. Docker frontend/API работают на 3001/8081; через них проверены реальные вопросы и генерация карточки. Автоматические тесты используют отдельные API 8180 и БД `larda_ui_test` с явным fallback, чтобы не вызывать внешнюю модель. Тестовый API не является постоянным сервисом.
- Эти процессы локальные; перезапуск после остановки описан ниже. Dev-порт 5173 оставлен пользователю.

## Общий запуск через Docker Compose

Из корня репозитория:

```bash
docker compose up --build -d --wait
```

Откройте http://localhost:3000. Сервис `web` отдаёт React-сборку и проксирует `/api` в `api:8080`; API работает с сервисом `db`. Браузер обращается к одному origin. `WEB_PORT`, `HTTP_PORT`, `POSTGRES_PORT` можно задать в `.env`, не перезаписывая существующий файл.

`docker compose down` останавливает сервисы; не добавляйте `-v`, если нужно сохранить данные. На этой машине Docker запущен пользователем через sudo с портами 3001/8081/5433; [точная команда пересборки с CORS для Vite и Docker](DOCKER_QUICKSTART.md). Нативный Go с Podman БД остаётся отдельным запуском на 3000/8080/55432. Их данные автоматически не синхронизируются.

## Разработка через Podman и Go

Один раз создать БД (если контейнер с таким именем ещё не создан):

```bash
podman run -d --name larda-integration-db \
  -e POSTGRES_DB=larda -e POSTGRES_USER=larda -e POSTGRES_PASSWORD=larda \
  -p 127.0.0.1:55432:5432 \
  -v larda-integration-db:/var/lib/postgresql/data \
  docker.io/library/postgres:16-alpine
```

Если контейнер уже существует и остановлен: `podman start larda-integration-db`.

Запустить API в первом терминале:

```bash
AI_MODE=openai \
DATABASE_URL='postgres://larda:larda@127.0.0.1:55432/larda?sslmode=disable' \
HTTP_ADDR=127.0.0.1:8080 \
go run ./cmd/api
```

Во втором терминале:

```bash
npm install
npm run dev
```

Откройте адрес Vite (обычно http://localhost:5173). `/api` и `/healthz` проксируются в `http://127.0.0.1:8080`. Для другого порта API задайте `API_PROXY_TARGET`. Для просмотра сборки: `npm run build` и `npm run preview -- --host 127.0.0.1 --port 3000 --strictPort`.

## Подключение внешнего AI

На backend настройте `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` и `AI_MODE=openai` через `.env`, затем перезапустите API. Не добавляйте ключ в переменные `VITE_*` и не отправляйте его из браузера. Docker Compose читает backend `.env`.

`fallback` подписывает источник конкретной оценки. Ошибка внешней модели отображается как ошибка задачи, автоматической подмены на fallback нет. Через Docker frontend успешно проверены два внешних AI-задания. Текущий режим доступен через `/api/v1/runtime`; подробности в [AI_CONNECTION.md](AI_CONNECTION.md).

## Сквозной показ

1. Выберите бизнес-профиль, создайте задачу с описанием.
2. Дождитесь вопросов. Отвечайте по одному; «Назад» сохраняет ввод. После последнего ответа нажмите «Подготовить карточку» — ответы отправятся одним запросом.
3. Проверьте карточку и при необходимости сохраните правки. После оценки отметьте подтверждение фактов и опубликуйте.
4. Выберите профиль **капитана**, откройте задачу в каталоге и нажмите «Подать заявку». Заполните идею, затем план; проверьте и отправьте. Обычный участник подать её не может.
5. Бизнес открывает «Заявки и результаты», выбирает команду и нажимает «Добавить этап». Сохраните критерии; награда команды доступна в дополнительных настройках.
6. Капитан во вкладке «Моя команда» нажимает «Сдать этап» и отправляет HTTP(S)-ссылку. Бизнес принимает результат или возвращает на доработку.
7. После принятия этапов бизнес отдельно завершает работу команды и всю задачу.
8. Студент открывает «Мой прогресс»: серверный XP, достижения, завершённые работы и ссылки. Обновление страницы и смена профиля читают ту же БД.

Профиль и выбранная задача находятся в URL (`?user=...&view=...&task=...`); доступны refresh, назад/вперёд и прямые ссылки каталога. Изменение demo-ID в URL не является безопасным входом в аккаунт.

## Проверки

```bash
npm run build
npm run test:e2e
API_PROXY_TARGET=http://127.0.0.1:8180 npm run test:live
TEST_DATABASE_URL='postgres://larda:larda@127.0.0.1:55432/larda_ui_test?sslmode=disable' go test ./...
go vet ./...
```

`test:e2e` запускает локальный режим и HTTP-контрактные тесты на 4175. `test:live` запускает серверный frontend на том же изолированном порту и требует уже запущенный API. Не запускайте эти команды одновременно. Live-тест **создаёт** задачу «Проверка интеграции …», заявку и принятый этап в подключённой БД. Используйте локальную проверочную БД. Для команды выше заранее запустите API на 8180 с `AI_MODE=fallback`, `DATABASE_URL` этой отдельной БД и `CORS_ORIGINS=http://127.0.0.1:4175`. Не подключайте fallback-worker к той же БД, которую обрабатывает внешний AI: оба worker читают общую очередь. PostgreSQL-тесты Go используют отдельные случайные схемы.

## Что отличается от локальной геймификации

Backend — источник правил и начислений: несколько команд на задачу, произвольные этапы, распределение XP среди текущих участников и серверный каталог достижений. Уровень отображается по серверному XP. Навыки профиля обозначены как заявленные, а не подтверждённые конкретным личным вкладом.

Ранг, персональная атрибуция вклада, сроки и история версий из старой локальной модели не объявлены серверной функциональностью. Старый вариант доступен через `npm run dev:local`; он не мигрирует демонстрационные записи в PostgreSQL. В серверном UI пока нет управления командами/файлами; список задач ограничен 100 записями. Production-auth и проверка юридического статуса бизнеса не реализованы.
