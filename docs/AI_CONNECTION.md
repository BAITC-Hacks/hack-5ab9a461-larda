# Проверка подключения ИИ

Браузер не вызывает модель напрямую. Он отправляет задачу в Go API, а серверный worker читает `AI_MODE`, `OPENAI_API_KEY`, `OPENAI_MODEL` и `OPENAI_BASE_URL` при запуске. Переменные запущенного процесса имеют приоритет над `.env`. После изменения `.env` нужно перезапустить API; обновления страницы недостаточно.

## Какой режим сейчас работает

```bash
curl http://localhost:5173/api/v1/runtime
```

Для Docker замените адрес на `http://localhost:3001`. Endpoint возвращает только `{"ai_mode":"openai"}`, `{"ai_mode":"fallback"}` или `{"ai_mode":"unknown"}`; ключ, модель, URL провайдера и данные задач не раскрываются. Ответ не кешируется. На старом образе `/runtime` вернёт 404 — пересоберите API командой запуска из [Docker-инструкции](DOCKER_QUICKSTART.md).

`openai` означает настроенный внешний провайдер, но успешность конкретного запроса проверяется отдельно: новая задача должна завершить AI-задание со статусом `succeeded`, а её `draft_evaluation.source` — стать `openai`. Ошибки провайдера сохраняются в `ai_error`; автоматической подмены ответа режимом fallback нет.

Сохранённые оценки не меняются после перезапуска: `fallback` у старой задачи — источник прежней оценки, `demo_seed` — начальные синтетические данные. Это не показатель текущей конфигурации сервера. Новая сохранённая правка карточки запускает переоценку; повтор уже успешной генерации вопросов отдельно не предусмотрен.

## Не перепутать локальные серверы

- `API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev` подключает Vite к Docker API на 8081.
- Без override Vite использует `API_PROXY_TARGET` из `.env` или API на 8080.
- Docker frontend проксирует API к контейнеру `api`; внешние порты Vite на него не влияют.
- `VITE_DATA_MODE=local` — отдельная локальная демонстрация. Она не обращается к серверному ИИ.

Ошибка `403 origin is not allowed` означает, что origin браузера отсутствует в настройках работающего API. Например, localhost и 127.0.0.1 — разные origin. Теперь Compose автоматически добавляет оба адреса своего WEB_PORT и Vite 5173 через WEB_ORIGINS, сохраняя дополнительные CORS_ORIGINS. Пересоздайте контейнеры с прежними портами (обычный restart не применяет новые переменные):

```bash
sudo env WEB_PORT=3001 HTTP_PORT=8081 POSTGRES_PORT=5433 \
  docker compose up --build --force-recreate -d --wait
```

Для внешней модели требуется `AI_MODE=openai`. Ключ остаётся только на сервере: не используйте переменные `VITE_*` для секретов. При запуске Go с ранее экспортированным `AI_MODE=fallback` уберите этот override; `.env` не заменяет уже заданные переменные окружения.

## Фактическая проверка 2026-09-23

Через Docker frontend на 3001 создана синтетическая приватная задача: внешний провайдер успешно сформировал семь вопросов, затем карточку по семи ответам. Оба задания завершились с `source=openai`; после проверки задача архивирована. Старый нативный API на 8080 был запущен с принудительным `AI_MODE=fallback`; перезапущен с настройками `.env` и прежней БД на 55432. Настройки и секреты `.env` не изменялись.
