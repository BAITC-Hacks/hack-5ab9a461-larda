# Запуск Larda через Docker

Compose включает весь проект: `db` (PostgreSQL), `api` (Go + ИИ), `web` (React-сборка + nginx). Фронт отдельно через npm запускать не нужно. Браузер обращается к одному адресу; nginx направляет `/api` в контейнер API. `.env` с ключом ИИ сохраняется и не копируется в frontend-образ.

## Пересобрать на этой машине

Docker уже работает на 3001/8081/5433. Порт 3000 занят отдельным локальным preview, 8080 — нативным API с другой БД. Чтобы обновить существующий Docker-запуск и сохранить его volume:

```bash
cd /home/shindenis/programming-projects/hackalem/hack-5ab9a461-larda
sudo env WEB_PORT=3001 HTTP_PORT=8081 POSTGRES_PORT=5433 \
  docker compose up --build --force-recreate -d --wait
```

Откройте **http://127.0.0.1:3001** или **http://localhost:3001**. После пересборки обновите вкладку браузера. `--force-recreate` обновляет окружение и nginx-соединение с API; данные в volume остаются. `restart` не применяет новый код и переменные.

Из этой сессии агент не имеет доступа к Docker socket; требуется команда в пользовательском терминале. Образы и nginx проверены отдельно через rootless Podman. Пароль sudo вводится только в терминале.

## Обычные порты

Если 3000, 8080 и 5432 свободны, используйте значения `.env` или:

```bash
sudo env WEB_PORT=3000 HTTP_PORT=8080 POSTGRES_PORT=5432 \
  docker compose up --build --force-recreate -d --wait
```

Адрес фронта — http://127.0.0.1:3000. Не запускайте эту команду поверх текущего локального preview на том же порту. Сначала остановите именно соответствующий локальный процесс. Значения `env` действуют только на одну команду; при следующем `up` используйте прежние порты либо сохраните их в `.env`.

## Почему была ошибка 403

`http://localhost:3000` и `http://127.0.0.1:3000` — разные origin. Старый запущенный API разрешал первый, но отклонял второй ещё до обработки задачи или заявки. Правильная строка в `.env` не меняет уже работающий процесс.

Теперь Compose передаёт `WEB_ORIGINS`, вычисленные из `WEB_PORT`: оба loopback-адреса фронта и оба адреса Vite на 5173. Backend объединяет их с `CORS_ORIGINS`. Старый явный список другого порта больше не блокирует текущий Compose-фронт. Проверка origin остаётся точной; wildcard и подмена заголовка Origin не используются.

Для внешнего домена добавьте его точный origin в `CORS_ORIGINS` и пересоздайте API. При нативном запуске Go также нужен перезапуск после изменения `.env`.

## Проверка и разработка

```bash
sudo docker compose ps
curl http://127.0.0.1:3001/healthz
curl http://127.0.0.1:3001/api/v1/runtime
```

Ожидается `status: ok`; runtime показывает настроенный режим ИИ. Healthcheck `web` проверяет и HTML, и проксированный `/healthz`. Успешный runtime не доказывает успешность конкретного AI-задания: [диагностика ИИ](AI_CONNECTION.md).

Для отдельного dev-фронта с Docker API:

```bash
API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev
```

Откройте http://localhost:5173. Текущий Compose разрешает оба адреса Vite автоматически. Для явного демо без внешней модели можно добавить `AI_MODE=fallback` после `sudo env`; `openai` требует серверного ключа.

## Диагностика и остановка

```bash
sudo docker compose logs --tail=80 api web
sudo docker compose stop
```

Не используйте `down -v`, если хотите сохранить БД. Docker использует volume `larda_postgres_data`; данные прежнего Podman-запуска автоматически туда не переносятся. Нативный preview на 3000 и Docker на 3001 — отдельные базы и процессы.
