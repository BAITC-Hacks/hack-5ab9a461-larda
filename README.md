# Larda — реальные задачи, подтверждённый опыт

MVP для AI Sana / HackAlem: бизнес формулирует проблему, выбирает студенческую команду и принимает результаты. Студенты получают опыт за принятую работу.

Основной режим подключён к Go API и PostgreSQL. Полный сценарий проверен с серверным AI fallback; отдельно через Docker проверены настоящие OpenAI-запросы вопросов и карточки. Доступ демонстрационный, без production-авторизации. Начальные задачи и команды синтетические; новые формы сохраняют введённые пользователем данные.

При работающем API на 8080:

```bash
npm install
API_PROXY_TARGET=http://127.0.0.1:8080 npm run dev
```

При Docker API на 8081 используйте `API_PROXY_TARGET=http://127.0.0.1:8081`. Откройте адрес Vite, обычно http://localhost:5173. Backend должен разрешать этот origin. Ключ модели хранится только на сервере, не в `VITE_*`.

## Рабочее пространство

Бизнес: **Рабочий стол · Мои задачи · Отклики и проекты**. Студент: **Каталог задач · Мои проекты · Мой прогресс**. Обе роли используют общую светлую тему. Каталог, формы и профиль — отдельные экраны.

1. Бизнес нажимает «Создать задачу», описывает проблему и отвечает на уточнения по одному.
2. Проверяет подготовленную карточку, сохраняет правки, подтверждает факты и отдельно публикует задачу.
3. Капитан команды открывает задачу в каталоге: «Подать заявку» → идея → план → проверка и отправка.
4. Бизнес рассматривает заявку, выбирает команду и добавляет согласованные этапы с критериями.
5. Капитан отправляет ссылку на результат; бизнес принимает этап или возвращает на доработку.
6. Бизнес завершает работу команды и задачу. В «Моём прогрессе» отображаются серверный XP, достижения и ссылки на принятые результаты.

«Назад» сохраняет ввод между шагами. Закрытие формы заявки внутри той же задачи тоже сохраняет её черновик. Перезагрузка или уход в другой раздел не сохраняет несохранённый текст. Промежуточные переходы и polling не создают AI-заданий или заявок повторно. Ошибка чтения после успешной отправки не отменяет сохранённый результат.

Профиль, раздел и задача находятся в URL (`user`, `view`, `task`); работают прямые ссылки, refresh и история браузера. Выбор демопрофиля не является безопасным входом в аккаунт.

## Серверные правила и ограничения

- Любая опубликованная задача доступна в каталоге; низкая готовность не блокирует заявку. Готовность постановки отделена от исполнения.
- Принятие заявки начинает работу команды. Backend допускает несколько команд и произвольное число этапов.
- XP выдаёт только сервер; награда этапа распределяется между текущими участниками. UI не начисляет локальные баллы.
- Уровень вычисляется по серверному XP. Навыки профиля обозначены как заявленные; принятые результаты команды доступны отдельно.
- Персональная атрибуция вклада, ранг, фиксированные три этапа, сроки и история версий из локальной модели не выдаются за серверные возможности.
- Нет production-auth, подтверждения юридической личности бизнеса, управления командами и загрузки файлов через UI. Каталог ограничен 100 задачами.
- ИИ выполняется на backend асинхронно. `GET /api/v1/runtime` показывает настроенный режим; источник конкретной оценки находится в задаче. Ошибка внешней модели не включает fallback автоматически.

## Локальное демо

`npm run dev:local` включает отдельный прежний WorkspaceRepository с синтетическими данными и `sessionStorage`. Здесь реализованы три фиксированных этапа, личный вклад, ранги E–S, достижения, доказательства навыков и атомарный локальный ledger. Данные не переносятся в PostgreSQL, и этот режим не включается при отказе API.

[Правила локальной геймификации](docs/GAMIFICATION.md) · [локальные маршруты и архитектура](docs/FRONTEND.md).

## Проверки и архитектура

```bash
npm run build
npm run test:e2e
API_PROXY_TARGET=http://127.0.0.1:8180 npm run test:live
```

Playwright использует изолированный порт 4175; два набора нельзя запускать одновременно. `test:live` требует отдельный запущенный API/БД и создаёт тестовые записи. Используйте явный `AI_MODE=fallback` на тестовом сервере, чтобы не вызывать внешний ИИ; подробности в [инструкции](docs/RUN_INTEGRATED.md). Для размещения frontend нужен SPA fallback на `index.html`.

Серверный интерфейс — `src/features/connected`, HTTP и загрузка данных — `src/data`, общие контролы и анимации — `src/shared`. `domain` и WorkspaceRepository обслуживают сохранённое локальное демо. Backend находится в `cmd/api`, `internal`, `migrations`.
