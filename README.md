# Larda — реальные задачи, подтверждённый опыт

Frontend MVP для AI Sana / HackAlem. Бизнес формулирует задачу, выбирает команду и принимает результаты. Студенты получают опыт за подтверждённый вклад в реальные проекты.

**Статус:** локальный интерактивный прототип на React, TypeScript и Vite. Внешний AI, backend и авторизация не подключены. Начальные карточки и пример профиля синтетические; новые формы сохраняют введённые пользователем данные.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес из вывода Vite (обычно `http://localhost:5173`).

```bash
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты включают доменные правила и браузерные сценарии; временный сервер работает на `127.0.0.1:4175` и завершается автоматически. Для размещения сборки нужен SPA fallback на `index.html`.

## Что работает

- Создание задачи, минимум три вопроса локального помощника, редактирование и ручное подтверждение.
- Прозрачная готовность 0–100, рекомендации с доступными баллами и реальный пересчёт после сохранения.
- Открытый каталог: сортировка по готовности и дате, фильтры по теме и готовности. Низкая готовность не запрещает публикацию или отклик.
- Отклики и ручной выбор одной команды; другие отклики не отклоняются автоматически.
- Три этапа: анализ, прототип, итоговая поставка. Критерии, даты и состав команды фиксируются при старте.
- Передача материалов по ссылке, версии результатов, обратная связь, доработка и принятие бизнесом.
- Бизнес-кабинет: очередь решений, просрочки, принятые этапы и завершённые проекты.
- Студенческий профиль: уровень, ранг E–S, XP, три достижения, навыки с доказательствами и подтверждённые проекты.
- Отдельный пример профиля только для просмотра; данные рабочего пространства он не изменяет.

## Готовность задачи

| Категория                       |   Баллы |
| ------------------------------- | ------: |
| Контекст и потребность          | 10 + 10 |
| Данные и материалы              |      20 |
| Ожидаемый результат             |      15 |
| Критерии успеха                 |      15 |
| Ограничения                     |      10 |
| Пользователи                    |      10 |
| Контакт и формат взаимодействия |   5 + 5 |

За непустое подтверждённое поле начисляется его вес. Это **полнота сведений, не качество текста или оценка AI**. Готовность: 0–39 требует уточнения; 40–69 рабочая; 70–89 готовая; 90–100 приоритетная.

Неопубликованные черновики приватны. Для публикации нужны название, контекст и явное подтверждение; порога 70 нет. Более полные задачи выше в каталоге. Ранг студента не ограничивает доступ.

## Прогресс и опыт

Бизнес подтверждает отдельных участников каждой поставки: анализ +200 XP, прототип +300 XP, итог +300 XP. За отклики, выбор команды, клики или непроверенные результаты XP нет. Повторное принятие не начисляет награду снова.

Прогресс проекта — доля принятых этапов: 0 / 33 / 67 / 100%. Готовность постановки и прогресс исполнения независимы.

Ранги требуют одновременно XP и завершённые проекты с подтверждённым вкладом: E 0/0, D 1000/1, C 2500/2, B 5000/3, A 10000/5, S 20000/10. Для уровня L требуется `50 × L × (L − 1)` XP.

Достижения: первый проект +100 XP; пять проектов +300 XP; проекты с тремя разными бизнес-аккаунтами +200 XP. Аккаунт бизнеса не означает подтверждённую юридическую компанию.

## Демонстрация

1. В роли бизнеса создайте задачу с коротким описанием; покажите рост готовности после ответов и дополнительных сведений.
2. Подтвердите публикацию, откройте каталог и отправьте предложение в роли студента.
3. Вернитесь к бизнесу, выберите команду, откройте проект и задайте критерии и сроки трёх этапов.
4. В роли студента отправьте результат со ссылкой, участниками и описанием их вклада.
5. Бизнес запрашивает изменения; студент отправляет новую версию. Затем бизнес подтверждает участников и принимает результат.
6. Покажите очередь решений бизнеса, XP студента и сохранение после refresh. Пройдите оставшиеся этапы для достижения и портфолио.

Студент выбирает задачу через «Каталог задач» в шапке или кнопку в профиле: `/student/catalog`. Обе роли используют общую светлую тему.

Быстрый путь для этапов: бизнес → задача «Снижение списаний кофейни» → отклик команды «Нова». Подготовленный профиль: `/student/example` (не начисляет XP в рабочем пространстве).

## Архитектура и границы

`app` — маршруты и provider; `domain` — правила и типы; `data` — repository и локальное хранение; `features` — сценарии; `shared` — общий UI и анимации.

Состояние сохраняется в `sessionStorage` (`larda.workspace.v2`). Миграция читает v1, сохраняет исходные тексты и отклики, пересчитывает готовность и не создаёт фиктивного опыта. Старый ключ остаётся для восстановления. Несохранённый ввод формы может потеряться при навигации; сохранение между устройствами отсутствует.

Принятие результата, награды и достижения сохраняются одной операцией. Ошибка записи не обновляет память приложения частично. Проверки демо-ролей и владельцев не заменяют серверную авторизацию.
