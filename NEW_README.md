## 🎯 The problem

Small and medium businesses often have real problems they want students to solve, but they struggle to turn them into clear technical tasks.

A business owner might say:

> “We want AI to help us increase evening sales.”

For students, this is not enough to start working.

At the same time, businesses may not understand technical terminology, expected scope, required data, or how to evaluate student proposals.

**ChallengeBridge closes this gap.**

---

## ✨ What we built

ChallengeBridge is an AI-powered platform connecting SMEs with student teams.

The business describes a problem in plain language.

AI then:

1. identifies missing information;
2. asks relevant clarifying questions;
3. converts the answers into a structured challenge;
4. helps make the challenge understandable for students.

The system then calculates a transparent **Task Readiness Score from 0 to 100**.

Students discover challenges, submit their solution proposal, and the business manually chooses which team to work with.

## 🤖 How AI works

AI is not used just as a chatbot.

It acts as a bridge between the business and the student.

### Step 1 — Business input

```text
We own a coffee shop.
Evening sales are low and we want to increase them.
```

### Step 2 — AI detects missing information

```json
{
  "missingFields": [
    "availableData",
    "successCriteria",
    "constraints"
  ]
}
```

### Step 3 — AI asks clarifying questions

```text
1. What sales data can you provide?

2. What result would you consider successful?

3. Are there any time or technology constraints?
```

### Step 4 — AI generates the challenge

```json
{
  "title": "Increase Evening Coffee Shop Sales",
  "context": "Sales decrease after 18:00",
  "users": "Coffee shop customers",
  "data": "3 months of sales history",
  "expectedResult": "Working prototype and recommendations",
  "successCriteria": "Increase evening sales by at least 10%",
  "constraints": "2 week implementation period"
}
```

AI never makes the final business decision.

All generated content can be edited and confirmed by the business before publication.

## 📊 Transparent Readiness Score

The readiness score is **not generated by AI**.

It is calculated deterministically so businesses and students can understand exactly why a task received its score.

| Category                |  Weight |
| ----------------------- | ------: |
| Context & business need |      20 |
| Data & materials        |      20 |
| Expected result         |      15 |
| Success criteria        |      15 |
| Constraints             |      10 |
| Users                   |      10 |
| Business communication  |      10 |
| **Total**               | **100** |

Example:

```text
Task Readiness

████████████████░░░░ 82 / 100

✓ Context                   20/20
✓ Data                      20/20
✓ Expected result           15/15
△ Success criteria          10/15
✓ Constraints               10/10
✓ Users                     10/10
△ Communication              7/10
```

Editing the task immediately recalculates the score.

# ⚡ Quick Start

## Prerequisites

Make sure you have:

```text
Node.js >= 20
npm >= 10
```

Check:

```bash
node --version
npm --version
```

---

## 1. Clone the repository

```bash
git clone YOUR_REPOSITORY_URL
cd YOUR_REPOSITORY
```

---

## 2. Install dependencies

```bash
npm install
```

---

## 3. Configure environment

Copy the example environment file:

```bash
cp .env.example .env.local
```

Then open:

```text
.env.local
```

and add your API key:

```env
LLM_API_KEY=your_api_key_here

LLM_BASE_URL=https://YOUR_LLM_ENDPOINT/v1

LLM_MODEL=YOUR_MODEL
```

> Never commit your real API key to GitHub.

---

## 4. Start the application

```bash
npm run dev
```

Open:

```text
http://localhost:3000
```

That's it.

---

## 🔑 Environment Variables

| Variable       | Required | Description                    |
| -------------- | -------- | ------------------------------ |
| `LLM_API_KEY`  | Yes      | API key for the LLM provider   |
| `LLM_BASE_URL` | Yes      | OpenAI-compatible API endpoint |
| `LLM_MODEL`    | Yes      | Model used for task analysis   |

Example:

```env
LLM_API_KEY=your_key

LLM_BASE_URL=https://api.example.com/v1

LLM_MODEL=model-name
```

```text

↓
```

## 🛡 Reliability

LLM APIs can fail or respond with invalid output.

Therefore AI output is validated before entering the application.

```text
LLM response
      ↓
JSON parsing
      ↓
Zod validation
      ↓
Valid?
 ↙          ↘
Yes          No
 ↓            ↓
Use it      Safe fallback
```

This prevents malformed AI responses from breaking the application.
